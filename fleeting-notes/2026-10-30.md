# Herdr, OpenCode, and rethinking software

chiubaca mcp — herdr native app is throwing a curve ball in my AI tooling just as I was getting used to opencode native app. a new agentic tool that is completely malleable. can do anything you want, nearly. it makes me re-think everything about what software really is in this new world we're in.

Reflections:
- The tools are converging in capability but diverging in *shape*: herdr is a terminal-native multiplexer scriptable from inside (panes/tabs), OpenCode is a coding agent with its own session/worktree model.
- When the agent can reshape its own environment, the line between "the tool" and "the thing being built" gets blurry. Software becomes less like a fixed artifact and more like a conversation that leaves a trail of code behind.
- Malleability vs. reproducibility: the more a tool can do, the more state lives in "how you got here" rather than in files. Powerful for exploration, fragile for handoff.
- Composability: both herdr (CLI-over-socket) and OpenCode (tool/skill model) bet on "small primitives + agent orchestration" rather than monolithic IDEs. That seems to be the winning shape right now.
