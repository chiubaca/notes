# Better AI prompting and 3D workflows for Gunfishing

## Main conclusion

The Angler pipeline is already strong: the concept-to-model match is good, the cel atlas and export checks are sophisticated, and the walk has readable weight and contact. Don't replace Blender wholesale with Tripo. Use Tripo for blockouts, props, and alternate designs; keep Blender for final topology, painted atlases, rigging, animation, and deterministic export.

## Prompting improvements

Short prompts work well inside a persistent visual session but are fragile for fresh agents and subagents. Use a structured request:

- **Goal**
- **Reference**
- **Observed problem**
- **Change only**
- **Must preserve**
- **Acceptance checks**
- **Output**

Example:

> Improve the casual walk's right-foot contact. The swing boot skims the supporting leg and the shoulder rotation starts too early. Increase clearance slightly and delay the shoulder reversal by about two frames. Preserve silhouette, cel atlas, equipment placement, and foot drift below 0.001 units. Render frames 1, 5, 11, 17, and 27 from both cameras, run the walk validator, and return the updated assets plus a before/after contact sheet.

Other rules:

- State invariants explicitly: palette, topology budget, sockets, naming, and export format.
- Ask for evidence: before/after renders and measurements, not "looks better."
- Change one hypothesis per pass.
- Give visual reviewers a fixed rubric and no editing access.
- Reserve stronger reasoning for spatial/art decisions; use cheaper models for reruns, checksums, documentation, and routine verification.

## 3D pipeline improvements

1. **Move character data out of Python.** Put palette, proportions, landmarks, materials, sockets, budgets, and thresholds in a single JSON/YAML spec. Keep Blender/Python scripts generic.
2. **Add real checkpoints.** Commit accepted milestones for silhouette, atlas, final character, and each animation pass. Keep blends, exports, scripts, and review sheets together.
3. **Separate slow phases.** Blockout → detail geometry → UVs → atlas bake → rig/animation → export/validation. Cache expensive intermediates.
4. **Make validation one command.** Produce a contact sheet, reference overlay, wireframes, palette check, GLB re-import/deformation test, foot-drift report, and browser screenshot from one script.
5. **Split base colour from cel shadow.** Maintain separate base-colour and shadow atlases so baked, unlit, dynamic toon, and PBR modes can switch cleanly without double shading.
6. **Use modifiers/geometry nodes for repeated detail.** Keep Python for one-off generation, UV baking, and export logic.

## Where Tripo fits

Current Tripo P2.0 offers native quad-dominant topology, multi-view input, regional Mesh Edit, auto-separated parts, auto-rigging, and animation presets. The Angler's polygon budget is within range.

Best uses:

- Props first: rod, reel, net, satchel, tackle box.
- Future character blockouts from consistent front/side/back views.
- Rapid silhouette exploration with several polycount variants.
- Broad animation previews before final Blender animation.

Still weaker than the current pipeline for:

- Exact facial and costume matching
- Custom painted cel shadows and seam placement
- Deterministic sockets and bone structure
- Calibrated walk timing and foot contact
- Reproducible code-driven revisions

Important: finish geometry before rigging because Tripo remeshing/editing can strip skeletal data. For an intentional baked cel look, preserve reference lighting rather than removing it.

## Cheap experiment

Test one prop rather than remaking the Angler:

1. Isolate a clean front/side/back reference.
2. Generate four P2 polycount variants.
3. Use Mesh Edit only for local failures.
4. Import into Blender.
5. Score with the same visual rubric.
6. Compare total time and manual fixes against the procedural build.

P2 API generation is roughly $1–$1.30 per model, so this is a low-cost way to decide whether Tripo belongs in the pipeline.

# Ladybird terminal mode in Rex

Ladybird’s `--headless=terminal` mode renders real compositor frames inside Kitty-graphics-capable terminals such as Rex. Rex handles graphics and input; a few lines of Lua can launch Ladybird in a split and bind shortcuts. Local setup still needs Ladybird installed, Rex terminfo configured (`rex terminfo setup`), and a small `~/.config/rex/init.lua` action.
